Agisci come un mobile app security reviewer specializzato in Expo / React Native.

Voglio fare un audit di sicurezza del frontend mobile.

Contesto:
- Expo app
- login con token
- comunicazione con Laravel API
- scansione barcode/QR
- dati operativi di magazzino e tracciabilità

Controlla:
1. come vengono salvati i token
2. se vengono usati storage insicuri
3. gestione logout
4. gestione token scaduti
5. presenza di dati sensibili nei log
6. uso di URL non sicure
7. esposizione di segreti nel client
8. deep link o route sensibili
9. gestione permessi fotocamera
10. stato debug e configurazioni rischiose

Regole:
- se i token sono in AsyncStorage, proponi migrazione a expo-secure-store
- verifica che non ci siano chiavi o segreti hardcoded
- suggerisci miglioramenti semplici e realistici

Output richiesto:
- vulnerabilità o anti-pattern trovati
- criticità
- fix consigliati
- fix rapidi applicabili subito
- checklist finale mobile security








Agisci come un full-stack security reviewer.

Voglio una checklist finale di sicurezza per il mio progetto:
- frontend Expo
- backend Laravel API
- Docker local/dev setup

Genera una checklist pratica e verificabile, organizzata per aree:
1. Auth
2. Authorization
3. Validation
4. API security
5. Secret management
6. Mobile token storage
7. Logging
8. Environment config
9. Production readiness
10. OWASP API Top 10 relevance

Per ogni punto indica:
- cosa controllare
- rischio
- come verificarlo
- fix consigliato

La checklist deve essere pensata per un MVP ITS serio, non per una enterprise app.




Adesso applica un passaggio finale di hardening al progetto.

Obiettivi:
- togliere debug e configurazioni insicure
- migliorare gestione errori
- aggiungere rate limiting base
- verificare authorization sugli endpoint sensibili
- rimuovere log sensibili
- migliorare validazione input
- verificare storage sicuro dei token lato Expo

Vincoli:
- non rompere il funzionamento attuale
- niente overengineering
- solo hardening pragmatico e adatto a MVP

Output richiesto:
- modifiche applicate
- file modificati
- rischi residui
- cosa fare prima di una demo o deploy
